## 0. 一句话现状

周、秦、漢三朝都已做到"帝王时间轴 → 收尾过渡页 → 战役沙盘"的完整链路（漢另有两处段间过渡，且过渡页已换成漢朝专属场景图）；**晋朝已做时间轴 + 两处过渡 + 十六国势力沙盘（316—420）**；**南北朝已做五行并行时间轴（8 页强制分页 + 动态行）+ 8 个易代节点 + 收尾沙盘（隋灭陈）**；**隋、唐、五代、宋、元、明、清七朝已完整**：时间轴可翻页（五代十国是九行并行）→ 收尾过渡 → **七盘沙盘**（唐统一 / 梁晋争霸 / 宋收列国 / 元灭宋 / 明北伐 / 清兵入关 / 辛亥革命）→ 下一朝（清回主页）。十二朝从主页可以一路滚到底。
**第四轮新增「历史档案抽屉」**：点帝王卡右上角「档」、点战报里的人名、点战报标题旁的「史料」，
右侧滑出一张 40% 宽的档案卷轴（文言原文 + 白话译文 + 关联），正文里的暗金词条可**无限下钻**（318 条词条），
顶部有面包屑与返回，背景只压暗不遮黑。

## 3. 必须守住的约定

### 3.1 时间轴：一个整数表达一切

`useEndgameStore.index` = "已推进到第几幕"，`0` 是战前。
**所有派生状态（哪些国已归、路线是否播完、是否一统）都从这个整数算出来**，不另存数组。
回退 = 把 index 改小，CSS 过渡自动倒放。
总步数不写死：`EndgameStage` 把 `events.length` 注入 `store.total`（周 6 / 楚汉 7 / 三国 3），
`isFinished` 用 `index === events.length` 判断。

### 3.2 朝代的收尾走哪条路

```ts
// fall.<id>.json
"next": { "kind": "endgame" }                    // 进沙盘（周、秦、汉）
"next": { "kind": "timeline", "page": 4 }        // 回时间轴某页（周·平王东迁、汉·王莽篡汉）
"next": { "kind": "home" }                       // 回主页（备用）
"back": { "page": "last" }                       // 上滚确认后落在哪页
```

> 过渡章节按 URL 的 chapter 取（缺省 `fall`）。汉有三章：`fall`（汉魏禅代）、`xin`（王莽篡汉）、
> `zhongxing`（光武中兴）；后两章是段间过渡，`next.page` 分别指回时间轴的第 4、5 页（0 基）。

### 3.3 末页入口按钮的文案来源

`emperorData.getDynastyClosingLabel()`：
1. 优先取**过渡页副题**（周=周室倾覆、秦=秦亡、汉=汉亡）
2. 没有过渡页才取沙盘副题

> 这里踩过坑：一度错取沙盘副题，导致周显示成"秦灭六国"。

### 3.4 段间过渡（西周→东周、西汉→新→东汉）

`DynastyDetail` 里的 `SEGMENT_INTROS` 支持**一个朝代多处**过渡：

```ts
{
  zhou: { seg_dongzhou: { chapter: 'dongqian', label: '平王东迁' } },
  han: {
    seg_xin: { chapter: 'xin', label: '王莽篡漢' },
    seg_donghan: { chapter: 'zhongxing', label: '光武中兴' },
  },
}
```

触发页不写死：由「目标分段第一位君主所在页」倒推上一页。
`useWheelPaging` 增加 `onLeavePage(from)` 钩子，返回 `true` 表示这次下滑被消费。

> **分页必须按分段切**（`DynastyDetail.pages`）：先把君主按 `segmentId` 分组，再组内每 3 人一页。
> 否则段长不是 3 的倍数时（新朝只有王莽 1 人），王莽会和光武挤在同一页，
> 段间过渡就没有合法插入点，只能错位播放。周（12/25）恰好整除，改造前后分页完全一致。
> 改 `PAGE_SIZE` 或加新朝代时，先确认「段首页」存在。

### 3.5 沙盘地图是可配置的

```ts
interface MapSpec {
  attacker: MapRegion
  regions: MapRegion[]
  rivers: string[]
  empireName?: string   // 第 0 幕合体名，仅声明了才显示
  ariaLabel?: string    // 地图无障碍名
  resetHint?: string    // 悬停攻方第二行：周=六国复其疆 / 楚漢=十八王复其疆
  points?: StrategicPoint[]  // 要地/关隘：只标方位，不参与推演
  successor?: { year: number; name: string }  // 攻方易代（三国 265 魏→晋）
}
```

- `MAPS` 只剩 `{ zhanguo }`；楚漢图在 `features/endgame/chuhanMap.ts`，三国图在 `features/endgame/sanguoMap.ts`，
  由 `EndgameStage` 按 `mapId === 'chuhan' / 'sanguo'` 取
- `MapRegion.aliveFrom / aliveTo` 已启用：`WarringStatesMap` 按当前年份过滤**尚未归入攻方**的势力
  （`currentYear` 由 `preYearValue` 与上一幕的 `yearValue` 推出）。已归入版图的势力不隐藏，否则疆域会缺块；
  未登场的势力画成 `.region-unborn` 虚线幽灵轮廓占位（不可点、无国名），避免开局地图缺一块
- `successor` 只换国号、不换版图：280 年灭吴时攻方显示「晋」，但疆域仍是魏的那一块
- 要地/关隘存在 `MapSpec.points`，楚漢/三国写在 geo JSON 的 `points`，战国写在 `STRATEGIC_POINTS`；
  `verify-map-points.mjs` 与两个几何脚本会校验它们确实落在所属疆域内
- `WarringStatesMap` 接收 `mapSpec`，攻方判定一律用 `mapSpec.attacker.id`，**内部不允许再出现 `'qin'` 这类字面量**（曾写死过，导致楚漢悬停「漢」没有"回到战前"提示）

### 3.6 一役兼灭多国

```json
{ "nationId": "xichu", "alsoCaptures": ["jiujiang"] }
```

`isCaptured()` 会额外检查 `alsoCaptures`。

> 但**能不用就不用**：九江曾靠这条被"顺带归汉"，结果时间轴上看不到它何时亡，最后被删掉了。
> 除非确实同一天灭亡，否则给独立节点。

### 3.6b 终章那个大字（统一者）

沙盘推演到最后一幕，屏幕中央会浮出一个巨大的红色国号。**它不是写死的"秦"**：

```json
// endgame.*.json
"unifiedName": "秦"   // 周之沙盘：秦统一六国
"unifiedName": "漢"   // 楚汉沙盘：汉统一天下（繁体「漢」，739b130 定稿）
"unifiedName": "晋"   // 汉之沙盘：三国归晋（攻方仍是魏，265 已禅晋）
```

`EndgameStage` 渲染 `endgame.unifiedName ?? dynasty.name`。

> 繁体「漢」是刻意的视觉选择，别"顺手"改成简体。统一者字样与下一朝无关，理由见下。

> 注意这是「**谁完成了统一**」，不是「下一朝」。
> 二者现在恰好一致，但汉末的沙盘做到三国归晋，统一者已是晋而下一朝未必同——保持独立字段，不要从 `next.dynastyId` 推。

### 3.7 过渡页的图片处理

`.fall-photo-wrap` 三层：

| 层 | 作用 |
|---|---|
| `.fall-photo` | 四边线性羽化（mask），亮度 0.95 |
| `::after` | 压边渐晕，边缘压成页面底色 |
| `::before` | 背光暗晕，抹平"照片黑 vs 页面灰"的亮度台阶 |

> 曾经三层都是径向，四角被叠成纯黑，图片看不清。**不要改回径向。**

### 3.8 谥法评价

`evaluation: 'good' | 'neutral' | 'bad'` 依据《逸周书·谥法解》，表达的是**制度评价**，不是历史功过。
秦朝因"秦废谥法"，三位全 `neutral`，`posthumousRule` 统一写"秦废谥法，无谥可循"。

汉朝有两处容易误会，都是照制度而非史评：
- 汉桓帝谥"桓"，《谥法》"辟土服远曰桓"是美谥，故 `good`——尽管后世史评不佳；
- 汉灵帝谥"灵"，《谥法》"乱而不损曰灵"是恶谥，故 `bad`；
- 少帝（懿、辩）、孺子婴、王莽无谥，一律 `neutral`，`posthumousRule` 写明"无谥"的缘由。

评价色现在同时用**边框**表达（周、漢及以后所有朝代共用）：
- `good` 金（#c9a227 / 亮 #f0d99b）、`bad` 赤（#a8443a / 亮 #e57a62）、`neutral` 青灰（#6f8b83 / 亮 #a9c8bf）；
- 2px 外框 + 顶部一道评价色光带，悬浮时外发光；历史画像不再把评价色"吃掉"。

### 3.9 南北朝时间轴：8 页分页 + 动态行 + 标准帝王卡（`NanBeiTimeline`，独立组件）

不在 `DynastyDetail` 的分页模型里，路由由 `DynastyRoute` 分流，只读 `nanbei.json`。

| 概念 | 规则 |
|---|---|
| 页窗口 | `PAGES` 常量，8 段首尾相接铺满 420—589，段尾正好是一个易代节点 |
| 存活行 | 政权与窗口求交（`p.start < to && p.end > from`），**没有活着的行不渲染**，行数 3/2/2/2/3/3/3/2 |
| 行拉伸 | `.nbc-rows` 是 grid，`grid-template-rows: repeat(activeRows, minmax(0, 1fr))`；行内不再画政权大色块（旧 `.nbc-polity` 已删），卡片垂直居中 |
| 帝王模块 | 一律是标准 `EmperorCard`（画像 / 谥法边框），**等大竖卡**（宽高比 0.72，高度 `min(行高-24, 180)`）；数据见 `nanbei.json` 的 `reign / portrait / events / posthumousRule`（由 `scripts/enrich-nanbei.mjs` 生成，画像 `public/portraits/nanbei-*.svg`） |
| 在位条 | 每张卡外面套 `.nbc-reign`：长度 == 在位年数（本页裁切，最短 2px），带两端小竖线；卡片**居中压在条上**，所以「插入图片」和「读出在位长短」两件事同时成立 |
| 落点 | 默认居中于在位条；同年连号即位时才做「不压前卡」的最小右推（条仍保持真实长度），越界则整行回推——**不为排布改动在位条** |
| 悬停 | 卡片两侧浮出事件枝（左=军事、右=政治·文教；贴边时合并到单侧 `data-flip`），不再上下展开；悬停时邻卡压到 0.32 透明度，避免事件枝和邻卡糊在一起 |
| 左列「当前在朝」 | 行名不再写死：大字 = **本页实际存在的政权**（`row.polities`，如页 3 是「齐」、页 7 是「北齐/北周/陈」），刷体字 + 行色光晕，翻页时随面板重挂载播 `nbc-polity-in` 入场动画；小字两行 = 行系谱 + 年段 |
| 易代高亮 | 政权在本页起点（±2 年内）新生时，`data-fresh` → 国号转金 + `nbc-polity-glow` 呼吸两轮 + 挂「易代」小签；未易代的页不标 |
| 翻页提示 | 每页顶部居中闪一条「上一页节点」提示（如「479 刘宋灭亡 · 萧齐代之」），3.4s 自动淡出；页 1 不显示。**这是为了看完过渡页回来时还记得自己翻到哪一朝** |
| 跨页帝王 | 在位横跨两页的（太武帝、孝文帝……）两页各出现一个**完整模块**，不是裁切条 |
| 比例尺 | **按页自适应**：`clamp((舞台宽 - 96 - 64 - 6) / 本页年数, 12, 96)` px/年。短窗口要放大（550—557 只有 7 年），但封顶 96 |
| 节点 | 每页只有一个（`year === to`），放在页尾 `GUTTER` 里；**点击 = 跳 FallStage 过渡章节**，不再是弹层 |
| 翻页 | 复用 `useWheelPaging`；`onLeavePage` 把「段末下滚」变成**进过渡页**（这就是强制分页的用意），footer 的「下一页」可直接跳页 |

> 舞台 `.nbc-stage` 是 `overflow: hidden`：任何不可见但占布局的绝对定位元素（例如节点气泡的 `::after`）
> 都会把 `scrollWidth` 撑出舞台，验收脚本会判失败。气泡的 `content` 因此只在 `:hover` 里生成。

### 3.12 段间过渡：改朝换代处裁剪时间轴（口径与白名单）

时间轴按 `segmentId` 分段，**段的边界就是裁剪点**；边界处不直接翻页，而是插一屏 `FallStage`。
触发点不写死页码：`SEGMENT_INTROS[dynastyId][segmentId] = { chapter, label }`，
由「该分段第一位君主所在页」倒推上一页（`DynastyDetail.tsx`）。

| 朝代 | 裁剪点 | 章节 key |
|---|---|---|
| 周 | 西周 → 东周（平王东迁） | `dongqian` |
| 汉 | 西汉 → 新 · 新 → 东汉 | `xin` / `zhongxing` |
| 晋 | 西晋 → 东晋（衣冠南渡） | `yongjia` |
| 唐 | 唐 → 武周 · 武周 → 唐 | `wuzhou` / `shenlong` |
| 五代 | 梁→唐→晋→汉→周（4 个易代节点） | `houtang` / `shijin` / `qidan` / `houzhou` |
| 宋 | 北宋 → 南宋（靖康之变） | `jingkang` |
| 清 | 后金 → 入关定鼎 | `ruquan` |

**没有段间过渡的三朝（隋、元、明）是刻意的**：分段只是年号/时势分期（开皇—大业、元初—守成—内乱—元末、
洪武—建文永乐—…），不是国号更易；与「秦只有一段、没有段间过渡」同一口径。别再给它们硬塞过渡页。

**五代是并行时间轴**（`WuDaiTimeline`），不走 `DynastyDetail` 的分页：5 页窗口 [907-923][923-936][936-947][947-951][951-960]，
每页页尾正好一个易代节点，`onLeavePage` 把「页末下滚」变成进过渡页；节点数据在 `wudai.json` 的 `nodes[].chapter`。
页码由 `PAGES` 决定，**不是** `PAGE_SIZE=3` 那套（子代理曾按 DynastyDetail 算错过一轮，别照那个改）。

**新章节的数据规格**（0 起的 `back` / `next` 页码要精确）：
```json
{ "dynastyId": "tang", "title": "武周革命", "subtitle": "唐室中绝", "lede": "…",
  "acts": [{ "id": "act_x", "year": "690年", "heading": "革唐为周", "lines": ["…"],
             "source": { "book": "《旧唐书·则天皇后本纪》", "text": "原文" }, "note": "…" }],
  "enterLabel": "…", "enterHint": "…", "next": { "kind": "timeline", "page": 2 }, "back": { "page": 1 } }
```

### 3.13 沙盘底板：真实省界 + 史实归属（旧 Voronoi 已废弃）

```
scripts/data/china-provinces-100000.json   省界真源（35 个 feature，含台港澳与南海，已排除）
        ↓ node scripts/build-china-base.mjs
scripts/data/china-cells.json              35 个地理单元（投影 1000×640、DP 简化、5 处省内切分）
        ↓ node scripts/make-sandbox-geo.mjs
src/data/<map>.geo.json                    每盘：attacker + regions（= 单元并集）+ rivers + points + successor
        ↓ node scripts/fix-campaign-geo.mjs
src/data/endgame.*.json 的 campaigns[].points  百分比坐标
```

- **地理单元**：省界 + 5 处切分（陕西 秦岭南北 / 山西 雁门南北 / 河北 燕山南北 / 江苏 淮河南北 / 安徽 淮河南北）。
  单元必须**平铺**整块大陆：面积和 208772、中心点各落一块、两两不重叠（`verify-sandbox` 校验）。
- **政权 = 单元并集**：在 `make-sandbox-geo.mjs` 的 `MAPS[id]` 里写 `cells: [...]`。
  并集必须**连片**，脚本发现「丢了碎片」会直接报错（曾经把「元」的西域丢出画面）。
- **背景势力**（突厥 / 契丹 / 大理 / 吐蕃 / 卫拉特…）标 `backdrop: true` → 输出 `neutral`，不参与推演、也不标国都。
- **要地 / 关隘**：`points[]` 必须落在其 `regionId` 的疆域内；标签方位由 `pickPointOffset` 自动避让。
- **国名排布**：`placeLabels` 先占国都与要地的文字块，再按面积从大到小给国名挑空位，
  放不下时自动缩字号（缩过的字号会写回 `labelSize`）。

### 3.13b 行军路线的坐标口径（**踩过的坑，别再踩**）

`CampaignRoutes` 的坐标系是**百分比**：`x*10`、`y*640/100` → viewBox 0..1000 / 0..640。
周 / 楚汉 / 三国 / 南北朝 四盘的数据是百分比（`{x:25,y:62.8}`）。
七朝沙盘第一版把 `points` 写成投影绝对坐标（`{x:272,y:332}`），渲染时被 ×10，
**整条线画到画布外**——数据齐全、几何验收还全绿，但用户看到的是「沙盘没有行军路线」。

现在的规矩：
1. `campaigns[].from / via[] / to` 写**地名**，是唯一真源；
2. 坐标一律 `node scripts/fix-campaign-geo.mjs` 生成（`scripts/lib/geo-lib.mjs` 的 CITY + `cities-hist.mjs` 的史书地名补表）；
3. `side` 由脚本判定：起点在目标境内、终点在攻方境内 → `enemy`（冷色，画敌方反攻），否则 `qin`（金色）；
4. `verify-sandbox.mjs` 会校验「x/y 都 ≤ 100」「端点不落到海里」「战报目标政权在版图里」。

## 4. 怎么加一个朝代（标准流程）

以"汉"为例：

1. `src/data/emperors.han.json` —— 每位帝王：
   `id / posthumousTitle / personalName / reign / startYear / endYear / segmentId / portrait / events[] / evaluation / posthumousRule`
   - `events` 每条要有 `dimension`（military / political / culture），**每张卡建议 ≤4 条**，横向排不下
2. `src/data/segments.han.json` —— 分段 + 段内标志点
3. （可选）`src/data/fall.han.json` —— 收尾过渡页，三幕 + 出处 + 注
4. `src/data/emperorData.ts` 注册：
   ```ts
   EMPERORS.han = hanRaw
   SEGMENTS.han = segmentsHanRaw
   FALL.han = fallHanRaw      // 只影响末页按钮文案，不提供章节数据
   ```
5. `src/features/fall/FallStage.tsx` 的 `CHAPTERS` 注册章节数据——**漏这步 `/fall` 打不开**：
   ```ts
   han: { fall: fallHanRaw, xin: fallHanXinRaw, zhongxing: fallHanZhongxingRaw }
   ```
   （`fall.<id>.<chapter>.json` 与 URL 里的 chapter 段一一对应）
   > 跨朝续接：`fall.<id>.json` 的 `next` 可加 `dynastyId`（如 `{ kind: 'timeline', dynastyId: 'tang', page: 0 }`），
   > 出口就落到下一朝而不是回本朝；清是 `{ kind: 'home' }`。
6. 画像：漢朝用 `public/portraits/han-*.webp`（630×780，历史画像检索所得；来源含《三才图会》系统、百度百科/360百科词条图，均为公有领域或历史插图）。
   其余朝代仍可跑 `node scripts/gen-placeholders.mjs` 生成程序化占位 SVG（漢朝已换成实图，不会再被它覆盖）。
7. 过渡页配图：每個 act 的 `art` 指向 `FallStage.ART` 里的键；漢朝 9 张图在 `src/assets/han-*.jpg`，
   由豆包生成后裁去角标再压缩为 1600×900。新朝代照此加 import + ART + ART_ALT 三项。
8. 若跨时段（如西漢→新→東漢），在 `SEGMENT_INTROS` 加段间过渡
9. 跑测试 + 截图验收

## 8. PowerShell 操作注意事项

这个项目用 pwsh 改文件，踩过的雷：

1. **here-string**：`@'...'@` 的结束符必须独占一行；`@"..."@` 内 `${}` 会被插值
2. `.Replace()` **替换所有匹配**，不是第一个 —— 改代码片段前先确认唯一性
3. **给 CSS 追加块后，删除时不要用正则切割**。曾把 `endgame.css` 切坏（多一个 `}`），整个沙盘 500 白屏
4. `git checkout -- <file>` 会被安全策略拦（`CC Safety Net`），弃改动用 `git stash push -m ... -- <file>`
5. 中文路径下 `Add-Type`/`System.Drawing` 读图可能报"路径形式不合法"，用 Pillow 更稳
6. `scripts/legacy/` 是九国版楚汉 geo 的废弃管线（含 `apply-chuhan-geo.mjs`），**永远不要运行**；
   当前真源是 `src/data/chuhan.geo.json` + `features/endgame/chuhanMap.ts`
7. 用 PowerShell `Set-Content -Encoding UTF8` 写 JSON 会**带 BOM**，Node 的 `JSON.parse` 会报
   `Unexpected token '﻿'`；改 JSON 一律用 node 脚本（`fs.writeFileSync`），或事后跑一遍去 BOM。

## 9. 已知的设计取舍

- **过渡页的三层图片效果**是刻意做重的，为了"照片不像贴图"。改轻会露出矩形边界。
- **每幕文字逐字浮现且必须走完才能翻页**，是用户明确要求；点击页面可跳过打字。
- **沙盘地图是示意图**，不是精确地理。但**面积守恒**和**无重叠**必须成立。
- **画像不是历史写真**：漢朝用检索所得的历史画像，其余朝代仍是程序化占位图（颜色 + 冠式 + 袍形），不要当成史料。
- **画像裁切以头部优先**：纵向尺寸不足时，从顶部锚定裁切（宁可切下摆，不切头冠）；少帝刘辩的全身线描像就是靠这条保住头部的，改裁切参数后要抽查末几页。
- **过渡页配图是 AI 生成的艺术再创作**（豆包）：汉 9 张 + 晋 6 张 + 南北朝 24 张 + 新七朝 21 张，共 60 张；一律裁去平台角标，仅作氛围，不是考古复原。
- **下滚 = 跳过当前一幕**：进入过渡页后的第一下惯性滚动会被 620ms 冷却吃掉；此后每下滚一次，直接结束当前幕的逐字并进下一幕（最后一幕则显示完、浮出入口）。点击页面仍然只跳过打字、不翻幕。
- **四张线描像统一做暖褐色彩化**（景帝、灵帝、献帝、少帝辩）：这四人没有可靠的彩色历史画像，网上能搜到的多数是剧照或同人图，故保留原线描、统一调成旧纸色，而不是混入影视截图。其余 23 张是彩色历代帝王像。
- **首页不再有「三国」模块**：三国（220—280）这段已由漢末沙盘「三国归晋」承担，主页只保留 12 个朝代模块（周秦汉晋南北朝隋唐五代宋元明清）。若将来要给三国做独立时间轴，才需要把 `history.data.json` 的条目与器物图加回来；不要为了凑数回加。
- **晋朝画像为程序化占位**：15 张全部 `jin-*.svg`，本轮明确不找图；过渡页 6 张为豆包生成的器物/场景图（无人物），裁去角标后压成 1600×900。
- **晋末沙盘是「势力变迁」不是「灭国战」**：`JinChronicleStage` 独立于 `EndgameStage`，路由用 `EndgameRoute` 分流；它只读 `jin.chronicle.json`，不碰 `mapGeometry` 的攻方/捕获模型。改区域归属只改 JSON 的 `control`，每一步必须覆盖全部 14 个区域 id。
- **南北朝是独立组件**：`NanBeiTimeline` 不进 `DynastyDetail` 的分页模型，路由用 `DynastyRoute` 分流；只读 `nanbei.json`。行由 `rows` + `polities` 的 `row` 字段决定，横向位置 = `(year - 本页 from) * scale`；改朝代/年份只改 JSON，窗口在组件里的 `PAGES`（改它要同步改 `verify-nanbei.mjs` 的首尾相接断言）。
- **南北朝节点已改为路由**：每页页尾节点 = 一章 FallStage（`/dynasty/southern_northern/fall/<节点 id>`），早期「弹层 overlay」的写法已废弃；`nodes[].acts` 仍留在 `nanbei.json` 里作为章节数据源。
- **南北朝时间轴是 8 页强制分页，不是横向滚动**：每页 = 一段年号窗口，页尾固定收一个易代节点；滚轮一次翻一页（冷却 520ms），末页再往下滚进收尾沙盘。旧的"自由横向拖动 + 16px/年"已废弃，别照旧笔记改回去。
- **每页只挂存活行**：卸载掉的行不占位，剩下的行按 1fr 分掉整屏高度；这既是"动态纵向空间释放"，也是 550—557 那页只有三行的原因（北魏已经没了）。
- **比例尺按页自适应，不做全局统一**：全局固定 16px/年会让 7 年那页压成一条缝，卡片只剩两个字的宽度；改成"本页铺满 + 封顶 96px/年"后每页都可读。代价是翻页时比例会变，这是刻意的。
- **南北朝收尾沙盘复用标准模板**：`EndgameStage + SUI_MAP`，不再用 JinChronicleStage；577 战报的 `battlePages` 内嵌 581 页，避免在底部多出一个「北周」容器。

- **七朝是「骨架优先」的产物**：链路完整可玩（时间轴 → 过渡 → 沙盘 → 下一朝），帝系数据每位 2—4 条事件属粗坯，可按需增补；沙盘同理，3—6 幕是「先能推演」的取舍
- **占位画像不冒充史料**：七朝 95 张全是 `portraitSvg` 程序化生成（颜色 + 冠式 + 袍形），与晋朝同一口径；要换实图按朝代单独补
- **无图过渡页是降级不是缺失**：`FallStage` 在 `ART` 里查不到 key 时整幕改单栏居中，**不要拿无关图兜底**
- **分段标志点要稀疏**：七朝每个分段最多 2 个标志点，且离段首至少 20 年（唐这种约 4.5px/年的长时段）；
  早先三个点挤在段首，「玄武门 / 贞观之治 / 灭东突厥」直接叠在段名上

- **七朝沙盘是「真实省界 + 史实归属」的示意图**（第二轮起）：底板是中国真实省界简化出的 42 个地理单元（第三轮又从 35 切细到 42），
  政权 = 单元并集，所以轮廓是真中国、边界是真山河省界；面积守恒基准 **208772**（战国/楚汉/三国/南北朝四盘仍是旧的 433135，两套不通用），
  单元无缺块、两两不重叠、国都/要地/路线端点在本块都成立。**别把旧的「种子点 Voronoi」改回来**——那样切出来的边界与史实疆域无关；
- **五代十国只在中原行挂帝王卡**：十国君主多为国主/王，不入帝系，行内改成「政权带」（国名 + 起止 + 开国者），
  与「十六国余部」同一口径；
- **谥法统一口径**：七朝 95 帝一律「本义曰字」，无谥/伪谥/追谥存疑的写缘由 → neutral；这张表就是唯一口径，别再单独发挥。
- **百科库不新造史料**：318 条全部从项目里已核对的数据长出来（战报的 `sourceText`、`figures`、帝王/诸侯结构化字段）。
  帝王原文只收查证过的 6 条，其余留白——**「看起来像真的」的引文比没有更糟**。
- **织链白名单**：只链具体人名 / 战役名 / 本名，不链「秦王」「齐」这类称号。
  试过链称号：「王翦深知秦王猜忌」被链到了谥号也叫秦王的子婴。
- **帝王出链口径**：【在位战事】严格按在位年（放宽 20 年会把漢惠帝链到前 202 的垓下，不成立），
  另加【同朝】前后主，保证每位帝王都有出链。
- **档案抽屉不做全屏黑遮罩、不做 blur**：只 `opacity: .5` 压暗 + 一层 `rgba(4,6,8,.26)` 的点击层。
  blur 会让 SVG 地图整棵树重栅格化，第三轮沙盘卡顿就是这个原因。
- **档案抽屉与 `useAppStore` 分开**：视图机是「第几层视图 + 选中谁」的纯状态机，
  抽屉是浮在任意页面之上的全局浮层；混在一起会让 `BACK` 同时承担「退视图」和「退抽屉」两种语义。
