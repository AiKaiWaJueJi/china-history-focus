## 1. 五分钟跑起来

```bash
npm install
npm run dev -- --port 5180     # http://localhost:5180，验收脚本默认打这个端口
```

三个容易踩的点：

1. **端口就是 5180**。验收脚本白名单里的地址是 `http://localhost:5180`，换端口要给每个脚本传 `APP_URL`。
2. **dev 与 build 的路径前缀不同**：dev 走 `/`，`npm run build` 会带 `/china-history-focus/`（GitHub Pages 子路径，见 [vite.config.ts](../vite.config.ts)），`App.tsx` 用 `import.meta.env.BASE_URL` 反推 `BrowserRouter basename`。**所以 `dist/index.html` 不能双击直接打开**。
3. **部署是 push 到 main 触发**：`.github/workflows/deploy.yml` = install → build → `cp dist/index.html dist/404.html`（SPA 深链接回退，不复制这一份用户按 F5 会白屏）→ 上传 → deploy-pages。线上已验证：主页、进朝代、深链接刷新都正常。

## 2. 验收：跑哪几条、预期什么数字

| 命令 | 条数 | 耗时 | 什么时候必须跑 |
|---|---|---|---|
| `npx tsc -b --pretty false` | — | ~10s | 每次改代码 |
| `npm run build` | — | ~1s（构建） | 提交前、部署前 |
| `node scripts/run-all-verify.mjs` | **32 套 / 845 条** | ~12 分钟 | 任何功能改动 |
| `node scripts/check-content-claims.mjs` | **10/10**（已含在 run-all 里） | 改过任何生平文本 |
| `node verify-journey.mjs` | **402 条** | ~8 分钟 | 改路由 / 页面结构 / 抽屉 / 沙盘链路 |
| `npm run verify:quotes` | **230 条原文**（230 通过 / 0 无映射跳过） | 热缓存 0.2 秒 | 动过任何原文、出处或 `source-pages.json` 时（冷启动要联网，约 200 次请求） |
| `npm run lint` | 0 error（28 条既有 warning） | ~1s | 可选 |

- 32 套的构成：几何 4 套（36 条）+ 数据层 2 套（`verify-codex` 32 + `check-content-claims` 10）+ UI 26 套（762 条）；逐套清单见 本文第二部分 §5.1。
  （旧文档写「820 条 / UI 752 条」是两处笔误：`verify-codex` 实际 32 条、UI 实际 753 条，2026-11-21 逐套对数时改正。）
- **`verify-journey` 不进 run-all**：它真的把十二朝从周点到清（十二朝接力），一遍 8 分钟；日常回归不必要，改结构必跑。
- **别同时开两个浏览器跑验收**：机器负载一高，时间敏感用例（悬停驻留）容易假红；单独跑更快也更稳。

## 5. 三条硬红线（改回去必炸）

1. **页面级滚轮 / ← → 必须先问 `isCodexOpen()`**。抽屉是浮层，但翻页监听挂在 `window` 上——不判断，用户读档案时底下那页会被翻走（滚够了还会送进过渡页）。已接：`useWheelPaging`、`FallStage`、`EndgameStage`、`JinChronicleStage`。
2. **百科条目的形状要在「生成」和「读取」两头兜**：`quotes / related / tags` 必须永远是数组；缺一个字段 = 抽屉 `.map()` 抛错 = React 卸整棵树 = 全页黑屏（2026-11-15 真发生过）。三层（生成器兜底 / `normalizeEntry` / `ErrorBoundary`）一处都别拆。
3. **沙盘行军路线坐标必须是百分比（0–100）**，由 `fix-campaign-geo.mjs` 从地名算出来。写成投影绝对坐标，数据齐全、几何验收全绿，但线会整条画到画布外。

其余「不可回退」的史实口径（赵军路线、楚郡归属、项燕之死两说、九鼎、晋帝系……）见 本文第二部分 §7。

## 6. 踩过的坑（省命清单）

| 坑 | 症状 | 教训 |
|---|---|---|
| 典制词条缺 `quotes` | 点「书同文」整页全黑，连返回都点不到 | 数据形状在「生」「读」两头兜 + ErrorBoundary；验收要断言**形状**，不只断言内容 |
| 抽屉抢滚动 | 读长档案时底层时间轴自己翻页 | 浮层打开时冻结页面级滚轮/键盘（`isCodexOpen`） |
| `will-change: transform` | 沙盘推近后文字糊成一片 | 整块 SVG 被预栅格化后位图放大；战报期间 `will-change: auto` |
| 背景 `blur` | 沙盘卡顿掉帧 | blur 会重栅格化整棵 SVG；抽屉只压暗不 blur |
| PowerShell 写 JSON | `Unexpected token` | `Set-Content -Encoding UTF8` 带 BOM；改 JSON 用 node 脚本 |
| `git checkout -- file` | 被安全网拦 | 弃改动用 `git stash push -m … -- <file>` |
| `scripts/legacy/` | 会把楚漢 geo 弄脏 | 废弃管线，**永远不要运行** |
| 时间敏感验收的计时基准 | 「阈值内已展开」偶发假红 | 计时从 `pointermove` 时刻起算，观测窗必须严格小于阈值（本轮 `verify-dwell` 修正的就是这个） |
| 沙盘底部节点语义 | 改完逻辑后各套 verify「点节点 → 读战报」全假红 | 点未打过的国家要先播行军；验收统一走 `scripts/lib/verify-rail.mjs` 的 `clickRailNode`（先关残留战报 → 确认补齐 → 跳动画 → 等新战报） |

## 3. 必须守住的约定

### 3.1 时间轴：一个整数表达一切

`useEndgameStore.index` = "已推进到第几幕"，`0` 是战前。
**所有派生状态（哪些国已归、路线是否播完、是否一统）都从这个整数算出来**，不另存数组。
回退 = 把 index 改小，CSS 过渡自动倒放。
总步数不写死：`EndgameStage` 把 `events.length` 注入 `store.total`（周 6 / 楚汉 7 / 三国 3），
`isFinished` 用 `index === events.length` 判断。

### 3.2 朝代的收尾走哪条路

```ts
// fall.<id>.json
"next": { "kind": "endgame" }                    // 进沙盘（周、秦、汉）
"next": { "kind": "timeline", "page": 4 }        // 回时间轴某页（周·平王东迁、汉·王莽篡汉）
"next": { "kind": "home" }                       // 回主页（备用）
"back": { "page": "last" }                       // 上滚确认后落在哪页
```

> 过渡章节按 URL 的 chapter 取（缺省 `fall`）。汉有三章：`fall`（汉魏禅代）、`xin`（王莽篡汉）、
> `zhongxing`（光武中兴）；后两章是段间过渡，`next.page` 分别指回时间轴的第 4、5 页（0 基）。

### 3.3 末页入口按钮的文案来源

`emperorData.getDynastyClosingLabel()`：
1. 优先取**过渡页副题**（周=周室倾覆、秦=秦亡、汉=汉亡）
2. 没有过渡页才取沙盘副题

> 这里踩过坑：一度错取沙盘副题，导致周显示成"秦灭六国"。

### 3.4 段间过渡（西周→东周、西汉→新→东汉）

`DynastyDetail` 里的 `SEGMENT_INTROS` 支持**一个朝代多处**过渡：

```ts
{
  zhou: { seg_dongzhou: { chapter: 'dongqian', label: '平王东迁' } },
  han: {
    seg_xin: { chapter: 'xin', label: '王莽篡漢' },
    seg_donghan: { chapter: 'zhongxing', label: '光武中兴' },
  },
}
```

触发页不写死：由「目标分段第一位君主所在页」倒推上一页。
`useWheelPaging` 增加 `onLeavePage(from)` 钩子，返回 `true` 表示这次下滑被消费。

> **分页必须按分段切**（`DynastyDetail.pages`）：先把君主按 `segmentId` 分组，再组内每 3 人一页。
> 否则段长不是 3 的倍数时（新朝只有王莽 1 人），王莽会和光武挤在同一页，
> 段间过渡就没有合法插入点，只能错位播放。周（12/25）恰好整除，改造前后分页完全一致。
> 改 `PAGE_SIZE` 或加新朝代时，先确认「段首页」存在。

### 3.5 沙盘地图是可配置的

```ts
interface MapSpec {
  attacker: MapRegion
  regions: MapRegion[]
  rivers: string[]
  empireName?: string   // 第 0 幕合体名，仅声明了才显示
  ariaLabel?: string    // 地图无障碍名
  resetHint?: string    // 悬停攻方第二行：周=六国复其疆 / 楚漢=十八王复其疆
  points?: StrategicPoint[]  // 要地/关隘：只标方位，不参与推演
  successor?: { year: number; name: string }  // 攻方易代（三国 265 魏→晋）
}
```

- `MAPS` 只剩 `{ zhanguo }`；楚漢图在 `features/endgame/chuhanMap.ts`，三国图在 `features/endgame/sanguoMap.ts`，
  由 `EndgameStage` 按 `mapId === 'chuhan' / 'sanguo'` 取
- `MapRegion.aliveFrom / aliveTo` 已启用：`WarringStatesMap` 按当前年份过滤**尚未归入攻方**的势力
  （`currentYear` 由 `preYearValue` 与上一幕的 `yearValue` 推出）。已归入版图的势力不隐藏，否则疆域会缺块；
  未登场的势力画成 `.region-unborn` 虚线幽灵轮廓占位（不可点、无国名），避免开局地图缺一块
- `successor` 只换国号、不换版图：280 年灭吴时攻方显示「晋」，但疆域仍是魏的那一块
- 要地/关隘存在 `MapSpec.points`，楚漢/三国写在 geo JSON 的 `points`，战国写在 `STRATEGIC_POINTS`；
  `verify-map-points.mjs` 与两个几何脚本会校验它们确实落在所属疆域内
- `WarringStatesMap` 接收 `mapSpec`，攻方判定一律用 `mapSpec.attacker.id`，**内部不允许再出现 `'qin'` 这类字面量**（曾写死过，导致楚漢悬停「漢」没有"回到战前"提示）

### 3.5b 底部「国家容器」与「下一章」按钮

`StepRail` 那排节点（战前 + 各灭国节点）与地图走**同一套**点击语义，`EndgameStage.handleStep` 是唯一入口：

| 点谁 | 行为 |
|---|---|
| 战前（value 0） | `handleReset()`：清行军、关战报、回 index 0（攻方也走这里） |
| 已打过（`order ≤ index`） | **回到那一幕**并展开它的战报（保留沙盘的可逆性，不重演行军） |
| 还没打过（`order > index`） | 交给 `handleConquer`：跳步先弹「补齐推演」，确认后播行军，播完才弹战报 |

- 早先是「点谁就 `setIndex` + 直接弹战报」，行军动画被整段吃掉；现在与点地图完全同构。
- **两个入口共用 `revealBattle(event, { syncIndex })`**（2026-11-18 批次 0 合并，原先 `handleStep` 复制了一份 `handleConquer` 的分支）：
  差异是**真实的两种意图**，不是重复代码——
  · 点地图上已归入的势力：`syncIndex: false`，只展开战报、**不动进度**（顺手看一眼，别把沙盘倒回去）；
  · 点底部节点：`syncIndex: true`，节点是时间线定位器，往回点必须真的退到那一幕。
  铃声音量随之分叉（导航 0.7 / 回顾 0.45），**是刻意保留的历史行为，别合并成一个值**。
- 顶栏右侧另有 `endgame-skip`（「下一章 · ⟨朝代⟩ →」）：不推进沙盘，直接进 `endgame.next.dynastyId` 的时间轴；
  `dynastyId === 'home'`（清的终章）时显示「回主页」。
- **改这套语义必须同步验收**：各套 verify 里"点节点 → 读战报"统一走 `scripts/lib/verify-rail.mjs` 的
  `clickRailNode(page, index, sleep, { closePanel })`（先关残留战报 → 确认补齐 → 派发 wheel 跳动画 → 等**新**战报）。
  **这是唯一一份实现**：`verify-endgame`（原自带 `railTo`）与 `verify-journey`（原内联一段）已改为调用它，别再写第四份。
  `closePanel: true` 用于"读完战报还要接着点终章按钮"的两个脚本。
  漏改会全假红，而且失败原因看起来像"战报没弹"。

**行军路线的可读性（2026-11-17 补）**
- 三色按势力分：攻方赤金 `#e59a3c` / 守军幽蓝 `#56a8d8` / 援军青玉 `#74c6a4`。
  援军那组 `<g>` 没有 side 类，早先根本没拿到 stroke——等于线不显示；现在单独给色。
- 播放中左下角有图例（`.campaign-legend`，只在 `!campaignDone` 时出现），解释这三种颜色。
- 说明文字（`.campaign-general` 将名 / `.campaign-result` 动向）：**16px / 13px，黑边 2.4px**，
  两者都按 `--map-zoom` 反算（镜头推近时字号不跟着放大）。
  **字号唯一真源**是 `.campaign-general` / `.campaign-result` 末尾那对 `calc(... / var(--map-zoom,1))`；
  **描边唯一真源**是 `.map-svg .campaign-caption text { stroke-width: 2.4px }`。
  2026-11-18 批次 0 删掉了前面两组死声明（15px / 12.5px、4.5px / 4px）——特异性更低、位置更靠前，写了从不生效，
  留着只会让下一个人以为"设定是 4.5px、只是没生效"而把正确的 2.4px 改坏。
  **已播段的文字保留半透明**，战报打开时（`data-settled='true'`）才全隐——
  每段只亮 2 秒，不留痕的话"整场战役怎么打"根本读不出来。

### 3.6b 终章那个大字（统一者）

沙盘推演到最后一幕，屏幕中央会浮出一个巨大的红色国号。**它不是写死的"秦"**：

```json
// endgame.*.json
"unifiedName": "秦"   // 周之沙盘：秦统一六国
"unifiedName": "漢"   // 楚汉沙盘：汉统一天下（繁体「漢」，739b130 定稿）
"unifiedName": "晋"   // 汉之沙盘：三国归晋（攻方仍是魏，265 已禅晋）

`EndgameStage` 渲染 `endgame.unifiedName ?? dynasty.name`。

> 繁体「漢」是刻意的视觉选择，别"顺手"改成简体。统一者字样与下一朝无关，理由见下。

> 注意这是「**谁完成了统一**」，不是「下一朝」。
> 二者现在恰好一致，但汉末的沙盘做到三国归晋，统一者已是晋而下一朝未必同——保持独立字段，不要从 `next.dynastyId` 推。

### 3.8 谥法评价

`evaluation: 'good' | 'neutral' | 'bad'` 依据《逸周书·谥法解》，表达的是**制度评价**，不是历史功过。
秦朝因"秦废谥法"，三位全 `neutral`，`posthumousRule` 统一写"秦废谥法，无谥可循"。

汉朝有两处容易误会，都是照制度而非史评：
- 汉桓帝谥"桓"，《谥法》"辟土服远曰桓"是美谥，故 `good`——尽管后世史评不佳；
- 汉灵帝谥"灵"，《谥法》"乱而不损曰灵"是恶谥，故 `bad`；
- 少帝（懿、辩）、孺子婴、王莽无谥，一律 `neutral`，`posthumousRule` 写明"无谥"的缘由。

评价色现在同时用**边框**表达（周、漢及以后所有朝代共用）：
- `good` 金（#c9a227 / 亮 #f0d99b）、`bad` 赤（#a8443a / 亮 #e57a62）、`neutral` 青灰（#6f8b83 / 亮 #a9c8bf）；
- 2px 外框 + 顶部一道评价色光带，悬浮时外发光；历史画像不再把评价色"吃掉"。

### 3.9 南北朝时间轴：8 页分页 + 动态行 + 标准帝王卡（`NanBeiTimeline`，独立组件）

不在 `DynastyDetail` 的分页模型里，路由由 `DynastyRoute` 分流，只读 `nanbei.json`。

| 概念 | 规则 |
|---|---|
| 页窗口 | `PAGES` 常量，8 段首尾相接铺满 420—589，段尾正好是一个易代节点 |
| 存活行 | 政权与窗口求交（`p.start < to && p.end > from`），**没有活着的行不渲染**，行数 3/2/2/2/3/3/3/2 |
| 行拉伸 | `.nbc-rows` 是 grid，`grid-template-rows: repeat(activeRows, minmax(0, 1fr))`；行内不再画政权大色块（旧 `.nbc-polity` 已删），卡片垂直居中 |
| 帝王模块 | 一律是标准 `EmperorCard`（画像 / 谥法边框），**等大竖卡**（宽高比 0.72，高度 `min(行高-24, 180)`）；数据见 `nanbei.json` 的 `reign / portrait / events / posthumousRule`（由 `scripts/enrich-nanbei.mjs` 生成，画像 `public/portraits/nanbei-*.svg`） |
| 在位条 | 每张卡外面套 `.nbc-reign`：长度 == 在位年数（本页裁切，最短 2px），带两端小竖线；卡片**居中压在条上**，所以「插入图片」和「读出在位长短」两件事同时成立 |
| 落点 | 默认居中于在位条；同年连号即位时才做「不压前卡」的最小右推（条仍保持真实长度），越界则整行回推——**不为排布改动在位条** |
| 悬停 | 卡片两侧浮出事件枝（左=军事、右=政治·文教；贴边时合并到单侧 `data-flip`），不再上下展开；悬停时邻卡压到 0.32 透明度，避免事件枝和邻卡糊在一起 |
| 左列「当前在朝」 | 行名不再写死：大字 = **本页实际存在的政权**（`row.polities`，如页 3 是「齐」、页 7 是「北齐/北周/陈」），刷体字 + 行色光晕，翻页时随面板重挂载播 `nbc-polity-in` 入场动画；小字两行 = 行系谱 + 年段 |
| 易代高亮 | 政权在本页起点（±2 年内）新生时，`data-fresh` → 国号转金 + `nbc-polity-glow` 呼吸两轮 + 挂「易代」小签；未易代的页不标 |
| 翻页提示 | 每页顶部居中闪一条「上一页节点」提示（如「479 刘宋灭亡 · 萧齐代之」），3.4s 自动淡出；页 1 不显示。**这是为了看完过渡页回来时还记得自己翻到哪一朝** |
| 跨页帝王 | 在位横跨两页的（太武帝、孝文帝……）两页各出现一个**完整模块**，不是裁切条 |
| 比例尺 | **按页自适应**：`clamp((舞台宽 - 96 - 64 - 6) / 本页年数, 12, 96)` px/年。短窗口要放大（550—557 只有 7 年），但封顶 96 |
| 节点 | 每页只有一个（`year === to`），放在页尾 `GUTTER` 里；**点击 = 跳 FallStage 过渡章节**，不再是弹层 |
| 翻页 | 复用 `useWheelPaging`；`onLeavePage` 把「段末下滚」变成**进过渡页**（这就是强制分页的用意），footer 的「下一页」可直接跳页 |

> 舞台 `.nbc-stage` 是 `overflow: hidden`：任何不可见但占布局的绝对定位元素（例如节点气泡的 `::after`）
> 都会把 `scrollWidth` 撑出舞台，验收脚本会判失败。气泡的 `content` 因此只在 `:hover` 里生成。

### 3.12 段间过渡：改朝换代处裁剪时间轴（口径与白名单）

时间轴按 `segmentId` 分段，**段的边界就是裁剪点**；边界处不直接翻页，而是插一屏 `FallStage`。
触发点不写死页码：`SEGMENT_INTROS[dynastyId][segmentId] = { chapter, label }`，
由「该分段第一位君主所在页」倒推上一页（`DynastyDetail.tsx`）。

| 朝代 | 裁剪点 | 章节 key |
|---|---|---|
| 周 | 西周 → 东周（平王东迁） | `dongqian` |
| 汉 | 西汉 → 新 · 新 → 东汉 | `xin` / `zhongxing` |
| 晋 | 西晋 → 东晋（衣冠南渡） | `yongjia` |
| 唐 | 唐 → 武周 · 武周 → 唐 | `wuzhou` / `shenlong` |
| 五代 | 梁→唐→晋→汉→周（4 个易代节点） | `houtang` / `shijin` / `qidan` / `houzhou` |
| 宋 | 北宋 → 南宋（靖康之变） | `jingkang` |
| 清 | 后金 → 入关定鼎 | `ruquan` |

**没有段间过渡的三朝（隋、元、明）是刻意的**：分段只是年号/时势分期（开皇—大业、元初—守成—内乱—元末、
洪武—建文永乐—…），不是国号更易；与「秦只有一段、没有段间过渡」同一口径。别再给它们硬塞过渡页。

**五代是并行时间轴**（`WuDaiTimeline`），不走 `DynastyDetail` 的分页：5 页窗口 [907-923][923-936][936-947][947-951][951-960]，
每页页尾正好一个易代节点，`onLeavePage` 把「页末下滚」变成进过渡页；节点数据在 `wudai.json` 的 `nodes[].chapter`。
页码由 `PAGES` 决定，**不是** `PAGE_SIZE=3` 那套（子代理曾按 DynastyDetail 算错过一轮，别照那个改）。

### 3.13 沙盘底板：真实省界 + 史实归属（旧 Voronoi 已废弃）

```
scripts/data/china-provinces-100000.json   省界真源（35 个 feature，含台港澳与南海，已排除）
        ↓ node scripts/build-china-base.mjs

- **地理单元**：省界 + 5 处切分（陕西 秦岭南北 / 山西 雁门南北 / 河北 燕山南北 / 江苏 淮河南北 / 安徽 淮河南北）。

### 3.13b 行军路线的坐标口径（**踩过的坑，别再踩**）

`CampaignRoutes` 的坐标系是**百分比**：`x*10`、`y*640/100` → viewBox 0..1000 / 0..640。
周 / 楚汉 / 三国 / 南北朝 四盘的数据是百分比（`{x:25,y:62.8}`）。
七朝沙盘第一版把 `points` 写成投影绝对坐标（`{x:272,y:332}`），渲染时被 ×10，
**整条线画到画布外**——数据齐全、几何验收还全绿，但用户看到的是「沙盘没有行军路线」。

现在的规矩：
1. `campaigns[].from / via[] / to` 写**地名**，是唯一真源；
2. 坐标一律 `node scripts/fix-campaign-geo.mjs` 生成（`scripts/lib/geo-lib.mjs` 的 CITY + `cities-hist.mjs` 的史书地名补表）；
3. `side` 由脚本判定：起点在目标境内、终点在攻方境内 → `enemy`（冷色，画敌方反攻），否则 `qin`（金色）；
4. `verify-sandbox.mjs` 会校验「x/y 都 ≤ 100」「端点不落到海里」「战报目标政权在版图里」。

### 3.14 历史档案抽屉（百科库 + 无限下钻）

**一句话**：点帝王、点战报人名、点战报标题，右侧滑出一张可无限下钻的历史档案；
抽屉正文里的暗金词条点下去，当前档案换成下一层，**不叠弹窗**。

**数据从哪来（关键取舍：不新造史料）**
`scripts/build-codex.mjs` 把项目里已经逐条核对过的数据汇编成 `src/data/codex.entries.json`：

| 类型 | 数量 | 来源 | 有什么 |
|---|---|---|---|
| 战役 | 49 | `endgame.*.json` 的每个事件 | `sourceText{原文,译文}` + report + highlights |
| 人物 | 59 | 战报里的 `figures` | bio + deeds |

**正文标记**：`[[显示名|条目id]]` 纯文本，生成器按「某人名 / 战役名 / 本名」白名单自动织入（约 142 处）。
白名单**不含「秦王」这类称号**——试过链称号，结果「王翦深知秦王猜忌」被链到了谥号也叫秦王的子婴。

**帝王不能是死胡同**：帝王条目末尾自动挂两块链接，所以「秦始皇 → 秦灭齐 → 王贲 → 王翦」能一路点下去
（`verify-codex.mjs` 用 BFS 断言「存在长度 ≥ 2 的下钻路径」）：
- 【在位战事】：**严格按在位年**取的战役，最多 4 条。早先放宽过 20 年想覆盖「居藩时打的仗」，
  结果漢惠帝（前195—前188）连前 202 年的垓下都链了进来，「同期」就不成立——宁严勿滥。
- 【同朝】：本朝上一位 / 下一位帝王。既是保底出链，也方便顺着朝代连续读。

**文言原文：统一真源 `scripts/data/codex.quotes.json`（2026-11-18 批次 1 起）**

原文是整个百科库**最容易被编造**的地方，所以它有一套独立规矩：

```json
{ "id": "cx_shutongwen", "work": "《史记·秦始皇本纪》",
  "text": "一法度衡石丈尺。车同轨。书同文字。", "translation": "…", "tier": "primary" }
```

- **四件套缺一不可**：`work` 出处 / `text` 文言原文 / `translation` 白话译文 / `tier` 出处层级；
  缺字段时 `build-codex.mjs` **直接抛错**，不是警告——宁可生成不出来，也不要生成一条「看起来像真的」的引文。
- **出处层级**：`primary` 一手（正史本纪/列传/志、先秦两汉文献本身）；`secondary` 转引（类书、后人注疏辑本、**伪古文/后人伪托之书**）。
  现存唯一一条 `secondary` 是《尚书·泰誓中》的「天视自我民视」——泰誓乃东晋所出伪古文，文字通行但非西周原件，`via` 里写明了这一层。
  转引**必须写 `via`**（转引链，如「《太平御览》卷四三八引，原书已佚」），抽屉里会显示一枚层级小签 + 转引行。
- **现状**：118 段（战役 49 由战报的 `sourceText` 自动带出，其余 69 段人工查证；一手 117 / 转引 1）。
  帝王 35 / 177（秦 3/3、晋 14/15、漢 11/27、周 4/37、唐/宋/明各 1）、诸侯 12 / 12、典制 22 / 22。
  另有 **1 位留白登记**（晋安帝，《晋书》明载其口不能言、动止非己出），见下「留白登记」一节。
  `verify-codex` 会打印一行「帝王原文覆盖」，看进度用它，别在这里抄数字。
- **怎么加**：`node scripts/check-source.mjs scripts/probes-x.json` 在维基文库定位原句（指定卷页最准）→
  抄录（简繁按项目统一用简体，長句可缩略但必须标「……」）→ 写译文 → 重跑 `node scripts/build-codex.mjs`。
- **机器复查（2026-11-19 起）**：`npm run verify:quotes` 把整本原文库回维基文库核一遍。
  当前 **50 / 50 通过，1 条无映射跳过**（《旧唐书·魏徵传》三镜之喻：维基文库旧唐书卷次里查不到原句，只有后人转引；
  宁可显示「跳过」，也不拿《隋唐两朝志传》这类演义去凑映射）。
  比对口径三条：① 页面取 wikitext 原文（繁体），我们的简体引文先经 MediaWiki 转 zh-hant 再比；
  ② 只比汉字与数字，标点与引号样式不参与（源文用“”，我们用「」，比标点等于自己给自己判红）；
  ③ 异体字（羣/群、於/于、彊/强、兾/冀、衞/衛、製/制）两边走同一张归一表。
  **它挡的是「整句编造」与「张冠李戴到另一卷」，挡不住语义误读**——缩略处的上下文仍要人眼看。
- 177 位帝王不可能人人有可靠原文，硬凑就是造假：**查不到就留白**，UI 只显示正文，不会留空框。
- **留白登记（`scripts/data/codex.no-quote.json`）**：查证过「确实没有」的条目在这里留个牌子（id + 理由），
  生成器把它挂到条目的 `noQuote` 字段，抽屉里显示一行「暂无可靠语录 · 理由」。
  硬规矩：必须写理由（≥8 字）、**必须与 quotes 互斥**（两边都写必然有一边错，生成器直接抛错）。
  存在这个字段 = 不是漏做，是做完的结论——用来防止下一个人（或下一个 AI）把同一批帝王重查一遍。

**典制 / 典故词条（`scripts/data/codex.extra.json`，22 条）**
郡县制、分封制、书同文、焚书坑儒、推恩令、察举制、九品中正制、科举制、三省六部、均田制、府兵制、
节度使与募兵、杯酒释兵权、五铢钱、开元通宝、交子、一条鞭法、摊丁入亩、改土归流、军机处、
海禁与一口通商、编户齐民。每条都有正文与 1—3 条出链（链到帝王或战役），接进正文后织成一张网。
2026-11-18 起**每条都配了一段文言原文**（在 `codex.quotes.json`，一手出处），`verify-codex` 有断言守着。

**状态机**：`src/store/useCodexStore.ts`，`navigationStack: string[]` + `direction: 1|-1`。
- `open(id)` 重置栈；`drill(id)` 压栈，但**若目标已在栈中则退回到那一层**（A→B→A 不会变成 A→B→A→B）；

**UI**（`src/features/codex/`）

  blur 会整棵树重栅格化（第三轮沙盘卡顿的同一个坑）；点击层只有 `rgba(4,6,8,0.26)`，不是全屏黑底。

**入口三处**：**帝王卡 / 诸侯卡整卡**（2026-11-17 起去掉右上角 24px 的「档」按钮：
`<article role="button">` + `aria-label` + Enter/Space，`cursor: pointer`；触屏本来就更好点）、
战报里的人物标签、战报标题旁的「史料」。旧的 `FigureModal` 已删除（`verify-codex-ui` 断言它不再出现）。

**两条踩过的坑（第五轮补上的）**

1. **缺字段 = 全页黑屏，不是样式问题**。22 条典制条目（`codex.extra.json`）只有
   `id/kind/name/body/related/tags`，没有 `quotes`；抽屉里 `entry.quotes.map()` 直接抛
   `TypeError: Cannot read properties of undefined (reading 'map')`，React 19 把整棵根树卸载，
   用户看到的是**全黑一片、连返回都点不到**。现在的三层保护，一处都别拆：
   - 生成器输出前兜底 `quotes / related / tags` 必须都是数组（`scripts/build-codex.mjs` §7）；
   - 读取层 `normalizeEntry`（`src/data/codex.ts`）再兜一次，旧生成物/手改 JSON 也不会崩；
   - `src/lib/ErrorBoundary.tsx` 包住页面与抽屉，真崩了也只是那一块出提示框，给「重试 / 关闭档案」。

2. **抽屉打开时，底层不响应滚轮与 ← →**。翻页/推进的监听都挂在 `window` 上，

   `EndgameStage`、`JinChronicleStage` 都已加。新增页面级滚轮/键盘处理时记得也加。

### 3.15 帝王 / 诸侯档案：结构化时间线

档案抽屉对 `kind === 'emperor' | 'lord'` 走 `ArchiveBody`，其余类型仍走纯文本 `RichText`。
**不是**另造一套数据：全部从 `emperors.*.json` / `lords.zhou.json` 的既有字段装配。

```
ArchiveBody
├── 头部：朝代 · 在位 · 谥法评价（美/平/恶，与卡片边框同色）
├── 谥法 / 霸业：posthumousRule 或 hegemonyNote
├── 在位要事：**全量** events，按年份升序
│   └── 点开：史实注解 + 年份/时代 + 类别 + 同年称霸的诸侯 + 可下钻的相关档案
└── 同朝：上一位 / 下一位（诸侯则是「同期诸侯」）
```

- **事件注解**在 `src/data/event-notes.json`（键 = 事件 id，跨朝唯一，426 个）。
  本轮覆盖 33 位重点帝王、共 110 条事件；**一条一查，没把握的宁可不写**——没注解的事件照常显示元数据，
  头部如实标「注解 N / 共 M」，不假装每条都有考据。
- **相关档案**由 `entryForEventName` 解析：先精确匹配，再退一步「事件名以条目名开头」取最长
  （「书同文·车同轨」→「书同文」）。不做模糊包含，避免错链。
- `hasStructuredArchive()` 拿不到记录时（南北朝 / 五代十国是独立时间轴，君主不在 `emperors.*.json` 里）
  自动退回纯文本正文，档案不会变空。
- 数据层新增 `getEmperorArchive / getLordArchive / lordsRulingAt`（`src/data/emperorData.ts`）：
  「同年称霸」用**称霸期**求交，与时间轴联动同一口径。
- **注意** `emperors.tang.json` 曾把唐玄宗与唐宣宗的 id 写成同一个 `tang_xuanzong`，生成器 `usedIds`
  静默跳过后者 → 唐宣宗整条不在库里、唐武宗的「下一位」链到玄宗。已改 `tang_xuanzong_2`。
  改任何 id 后都要 `node scripts/build-codex.mjs` 并核对 `counts`。

**生平**（`src/data/emperor-bios.json`）：33 位重点帝王的两三句白话生平，作为「传」的主干。
另有一句话记忆点（`emperor-taglines.json`，显示为谥法旁的虚线标签，如「煤山殉国」）与
「时代」一行（归属分段 + 段说明 + 春秋/战国的标志点）——都是**事实化写法**，不写「明君/昏君」。
没写的帝王不渲染这一块（不留"暂无"空框），头部另给「在位 N 年 · 本朝第 X / Y 位」。
生平与事件注解里的人名由 `linkify()`（`data/archive.ts`）在**运行时**织成 `[[名字|id]]`：
与 `build-codex` 同一套规则（长名优先、只用 character/battle/extra 的名字），
但手写数据不该为加一条链就跑生成器。已手写的标记原样保留，不会二次包裹。

**人物从哪来**（`scripts/data/codex.append.json` + `build-codex.mjs` §5c）：
战报数据里只会出现"该战出场的人物"，像冒顿单于、张良、魏徵这种贯穿型人物只能手写。
追加文件允许任意 `kind`，本轮加了 40 位，百科 319 → 359 条。
**改 id 或加条目后必须重跑生成器**，并注意 `usedIds` 要去重（生成器会在 `characters` 阶段登记人物 id，
否则追加条目撞 id 时静默产出重复条目——本轮修的就是这个洞）。

**正文渲染只有一份**：`RichText.tsx` 同时服务生成物（战役/人物/典制的 body）与手写数据（生平/注解）。

**过渡页引文**（`FallStage`）：`source = { book, text, translation? }`，页面上**上译文、下原文**
（虚线段隔开）。22 章 93 幕的 `translation` 已逐条补齐；缺字段时只渲染原文，不会留空块。



## 4. 怎么加一个朝代（标准流程）

以"汉"为例：

1. `src/data/emperors.han.json` —— 每位帝王：
   `id / posthumousTitle / personalName / reign / startYear / endYear / segmentId / portrait / events[] / evaluation / posthumousRule`
   - `events` 每条要有 `dimension`（military / political / culture），**每张卡建议 ≤4 条**，横向排不下
2. `src/data/segments.han.json` —— 分段 + 段内标志点
3. （可选）`src/data/fall.han.json` —— 收尾过渡页，三幕 + 出处 + 注
4. `src/data/emperorData.ts` 注册：
   ```ts
   EMPERORS.han = hanRaw
   SEGMENTS.han = segmentsHanRaw
   FALL.han = fallHanRaw      // 只影响末页按钮文案，不提供章节数据
   ```
5. `src/features/fall/FallStage.tsx` 的 `CHAPTERS` 注册章节数据——**漏这步 `/fall` 打不开**：
   ```ts
   han: { fall: fallHanRaw, xin: fallHanXinRaw, zhongxing: fallHanZhongxingRaw }
   ```
   （`fall.<id>.<chapter>.json` 与 URL 里的 chapter 段一一对应）

## 7. 史实口径（不可回退）

已经修正过的、容易被后人改回去的地方：

- **赵军路线**：上地 → 井陉 + 河内，**不是上党**
- **楚郡**：归《楚世家》，并在楚战报的「史实注记」写明避讳与「楚郡」存疑（梁玉绳《史记志疑》）
- **韩**：删掉苏秦"地不满千里"（年代不合）
- **齐**：改为齐王建发兵守西界 / 王建自燕南攻
- **项燕之死**：保留两说，写在楚战报「史实注记」：《王翦列传》"杀项燕" vs《秦始皇本纪》项燕自杀、立昌平君
- **九鼎**：《周本纪》记"入秦"；"沉于泗水"是晚出传说，页面须写明
- **烽火戏诸侯**：见于《史记》，但先秦无"举烽"之制，注中须标出这一层
- **二王并立**：幽王死后平王与携王并立，《左传·昭公二十六年》与清华简《系年》可证
- **《文侯之命》的归属存疑，按主流经说系于周平王，但不要写成定论**：《书序》称「平王錫晉文侯秬鬯圭瓚，作《文侯之命》」，历代经说多从之；而《史记·晋世家》把同类册命系于周襄王、晋文公，司马迁误记一说今人有专文辨正。**两说并存**，本条挂平王是基于《书序》，改回去或改成襄王之前先看清这层分歧。晋文侯名仇、字义和，故篇中「父義和」是对他的称呼
- **原文缺口四种状态不能混说**：`pending`（还没查完）/ `to-collect`（有本纪、待收录）/ `no-annals`（正史无本纪）/ `out-of-scope`（体例不收）——数据值不同、界面文案不同、结论也不同。把「我们还没做」写成「史料没有」是最容易犯的一类诚实度错误；反过来，把 `out-of-scope` 登记成留白同样在骗人（过程见批次 11）
- **周朝留白不是偷懒**：37 位周天子里 25 位已登记「查证过确实没有原文」，依据是《史记·周本纪》对应条目本身只记「某王崩，子某立」级别的纪事。**其中绝大多数周王没有任何记言**；判断依据可重建——例如《左传·桓公》全卷「王曰/王問/王謂/王告」零命中（仅叙事性的「王使」「王命」），《左传·庄公》仅两条「王曰」，一条是楚文王、一条是惠王问内史过。别为了覆盖率把这些改回「有原文」
- **周王的诰辞在《尚书》与《国语·周语》，不在《周本纪》**：《顾命》《康王之诰》《文侯之命》《吕刑》以及《国语》卷01（周语上）/卷02（周语中）/卷03（周语下）才是记言所在；《国语》在维基文库按卷建页，work 键沿用「《国语·周语中》定王论不用全烝之故」这种篇名后缀写法
- **唐朝帝纪的底本用《旧唐书》，《新唐书》只作互校**：《旧唐书》本纪多直录实录、诏令原文完整；《新唐书》本纪刻意简省改写，很多诏令只剩一句概括。读本纪用旧书、考志表用新书（项目里引《新唐书》的百官志/兵志/食货志是对的，那确实是新书好）。**《资治通鉴》《贞观政要》一律不作为出处**，它们不是一手，只能当归属互证
- **允许同一部正史内的列传补帝王言论**：唐太宗「以人为镜」在《旧唐书·魏徵传》而非帝纪；唐中宗「一朝见天日，誓不相禁忌」在《后妃传上》韦庶人条；唐敬宗「朕去意已定」在《裴度传》。用列传时 work 要写明篇名（如「《旧唐书·裴度传》」），别混成帝纪
- **《宋史》卷号是三位补零，与《旧唐书》相反**：`宋史/卷001`、`宋史/卷047`。写成 `卷1` 会「页面不存在」。跨书操作时这条最容易翻车
- **《宋史》卷047 一节三帝**：「瀛國公　益王　衛王」同页。恭帝=瀛国公、端宗=益王赵昰、末帝=卫王赵昺。**页面标题的编排还把「帝昺」放在「景炎二年」之前，是错的**——景炎二年至祥兴元年四月「昰殂」前全属端宗朝。切节要按内容，不能按标题
- **《续资治通鉴长编》可作出处**（宋人辑实录而成，非伪托）：宋太宗「在德不在险」不见于《宋史》帝纪（卷004/005 各只有 6 个「曰」，全是尊号谥诏），原文在《长编》卷十七迁都之争的「王又言」之下；仓库里 `song_taizu` 已有《长编》卷十六先例，同体例
- **宋帝的记言往往不在帝纪**：神宗本纪三卷（014/015/016）引号数 0/3/0 且全是诏文，他最好的话在《宋史·王安石传》熙宁七年大旱那场对答；光宗本纪（卷036）无一处「朕」，其八字御批「历事岁久，念欲退闲」反载于《宁宗纪一》。判断「这位帝王帝纪里没记言」要能给出这种可复现的计数，而不是感觉
- **降表、降附表文不得当语录**：钦宗、恭帝两朝帝纪塞满降表与金人迫胁之辞（如德祐二年杨应奎上传国玺的表文），一律不入库。但**不要一刀切**——钦宗在城破当天说的「上皇惊忧而疾，必欲之出，朕当亲往」是记言、不是表文，正是全卷唯一体面的一句

## 8. PowerShell 操作注意事项

这个项目用 pwsh 改文件，踩过的雷：

1. **here-string**：`@'...'@` 的结束符必须独占一行；`@"..."@` 内 `${}` 会被插值
2. `.Replace()` **替换所有匹配**，不是第一个 —— 改代码片段前先确认唯一性
3. **给 CSS 追加块后，删除时不要用正则切割**。曾把 `endgame.css` 切坏（多一个 `}`），整个沙盘 500 白屏
4. `git checkout -- <file>` 会被安全策略拦（`CC Safety Net`），弃改动用 `git stash push -m ... -- <file>`
5. 中文路径下 `Add-Type`/`System.Drawing` 读图可能报"路径形式不合法"，用 Pillow 更稳
6. `scripts/legacy/` 是九国版楚汉 geo 的废弃管线（含 `apply-chuhan-geo.mjs`），**永远不要运行**；
   当前真源是 `src/data/chuhan.geo.json` + `features/endgame/chuhanMap.ts`
7. 用 PowerShell `Set-Content -Encoding UTF8` 写 JSON 会**带 BOM**，Node 的 `JSON.parse` 会报
   `Unexpected token '﻿'`；改 JSON 一律用 node 脚本（`fs.writeFileSync`），或事后跑一遍去 BOM。

## 9. 已知的设计取舍

- **过渡页的三层图片效果**是刻意做重的，为了"照片不像贴图"。改轻会露出矩形边界。
- **每幕文字逐字浮现且必须走完才能翻页**，是用户明确要求；点击页面可跳过打字。
- **沙盘地图是示意图**，不是精确地理。但**面积守恒**和**无重叠**必须成立。
- **画像不是历史写真**：漢朝用检索所得的历史画像，其余朝代仍是程序化占位图（颜色 + 冠式 + 袍形），不要当成史料。
- **画像裁切以头部优先**：纵向尺寸不足时，从顶部锚定裁切（宁可切下摆，不切头冠）；少帝刘辩的全身线描像就是靠这条保住头部的，改裁切参数后要抽查末几页。
- **过渡页配图是 AI 生成的艺术再创作**（豆包）：汉 9 张 + 晋 6 张 + 南北朝 24 张 + 新七朝 21 张，共 60 张；一律裁去平台角标，仅作氛围，不是考古复原。
- **下滚 = 跳过当前一幕**：进入过渡页后的第一下惯性滚动会被 620ms 冷却吃掉；此后每下滚一次，直接结束当前幕的逐字并进下一幕（最后一幕则显示完、浮出入口）。点击页面仍然只跳过打字、不翻幕。
